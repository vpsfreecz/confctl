# Fixture registry and verification contract

This registry separates required coverage, implemented inputs and accepted observations. Source-derived facts are in [commands](commands.md) and [interfaces](interfaces.md). Fixture files and existing specs are not evidence that the differential suite passed. The separately named candidate is **confctl-go-prototype**.

## Ownership and artifacts

- Design owner maintains this catalogue, source links, required cases and intentional-change distinctions. Implementer owns executable fixtures, Go driver, fake tools, prototype and raw observation manifests. Lead coordinates commits/review and accepts evidence. Do not overwrite another owner's files to make a mismatch disappear.
- Implementation destination: `tests/compat/` for schema, cases, fixtures, package function, driver and immutable reference observations; repository-root `cmd/`, `internal/`, `extension/` and `site/` for bounded binary/SDK/site executables; `experiments/confctl-go/` for opt-in package definitions and documentation. Fixture family/case IDs below remain stable aliases in the coverage index.
- Each case record links one or more catalogue paragraphs and explicit source line/revision, input fixture digest, oracle observation path, candidate comparison path, evidence tier and state S/O/U/P. A planned ID without an observation remains U for runtime coverage. Record partial coverage of a family instead of checking off the whole family.
- Generated run artifacts belong under session-owned `work/2026-10-09-evaluate-confctl-rewrite-language/verification/compat/<run-id>/` and `verification/bench/<run-id>/`, with compact portable reference goldens under tests/compat. Keep raw bytes/events/manifests alongside normalized views. Exclude generated artifacts from unrelated repository changes and avoid committing secret/environment dumps.
- Baseline is immutable confctl cc40679d267165aecfa569128438bb55fe910268 plus pinned Gemfile.lock, Nix package function and tool/dependency revisions. Site fixtures use configuration ae670dc0d4a5d43adf9560da1a6a0a35925cd2e5 sources or audited minimal synthetic data. Candidate changes never regenerate reference expected values automatically.

The [schema](../../tests/compat/harness/schema.go) carries source references, argv/environment, synthetic files, semantic tool rules, causal constraints, normalizers and the `expected` destination. The [driver](../../tests/compat/cmd/compat/main.go) and [runner](../../tests/compat/harness/run.go) produce a run-specific `case.json`, `raw.json` and, when normalization/causal validation succeeds, `normalized.json`. The references linked above are accepted byte-for-byte copies of those normalized records, not candidate-derived values. For future cases, merely producing a normalized record or naming an `expected` destination does not establish acceptance.

To promote coverage, link the retained run manifest and raw artifacts to the exact fixture digest and package/source/tool identities, record whether the case completed, and obtain lead acceptance of the normalized reference. Keep the candidate comparison as a separate result. The minimum environment/provenance fields below apply even when some live in a run-level manifest rather than the per-case JSON. A changed fixture, oracle package or normalizer requires fresh evidence or an explicit reviewed equivalence argument. Never substitute the mutable working fixture for the captured `case.json` when diagnosing an earlier run.

Observed boundaries and continuing reconciliation obligations:

- **O:** `list-invalid-managed` exits64 with command help on stdout, invalid-argument text on stderr and no Nix calls. Its causal expectations describe parser rejection, not inventory evaluation.
- **O:** `list-postarg-option` (`ls alpha/site -o spin`) prints configured default columns for alpha/site and exits0; trailing `-o spin` does not select the spin-only column. The handler lacks `require_args!`; do not generalize that helper's rejection rule to every command.
- **O:** `list-attached-managed` (`-oname --managed no`) prints NAME and the unmanaged `.hidden` row. `list-cluster-negation` (`-Honame,spin --no-hide-header --managed all`) prints the NAME/SPIN header and all four ordered rows. These exact forms establish attached-value, clustered-switch and subsequent-negation behavior; other parser combinations remain U.
- **S/O:** `list-attributes-trace` (`ls -L --show-trace`) prints `name`, `spin`, `host.target`; its recorded Nix argv omits `--show-trace`. The source constructs `Nix.new` without forwarding the flag. Both the transcript and the tool boundary matter.
- `list-carried-checks` must contain the complete health-check schema to test valid carried metadata. Missing `standardOutput`/`standardError` in a synthetic command makes [RunCommand::Output](https://github.com/vpsfreecz/confctl/blob/cc40679d267165aecfa569128438bb55fe910268/lib/confctl/health_checks/run_command.rb#L16) dereference nil when [Machine#health_checks](https://github.com/vpsfreecz/confctl/blob/cc40679d267165aecfa569128438bb55fe910268/lib/confctl/machine.rb#L125) constructs it. Retain any such malformed-input failure separately; it does not establish failure for valid module-produced carried metadata.
- Metadata equality uses Ruby string conversion, while table false/nil/empty cells use `-`; Ruby array/hash display is not JSON serialization. Pin exact collection formatting to the packaged Ruby dependency. Likewise preserve blank-answer reprompting, actual PTY bytes and successful completion after handled offline status results.
- **O:** `list-numeric-metadata` retains all four rows through the integer equality filter and renders `9007199254740993`, `1.0` and `[9007199254740993, 1.0]`. Converting all JSON numbers to binary64 or treating `1.0` as integer `1` would not preserve this input's selection/display. Other numeric forms remain U.
- **O:** `site-kernels-error-value` observes successful `uname` output `error` and `error.` reducing to the displayed sentinel `error`: a prior selected entry stays unchanged, an absent selected entry stays absent, and an unselected nested value is preserved. No error-detail block is printed; the other successful host is saved and the command exits0.
- **O:** `site-kernels-failure-order` keeps table rows in inventory order, while `.hidden`'s faster SSH failure detail precedes alpha/site's slower failure detail. Both failed selected state keys are removed, the unselected key and successful host remain, and the command exits0. Error details follow completion insertion order, not a fixed hostname sort; other schedules may yield another valid order.
- Fixture-tool stdin consumption must be explicit where the invoked tool reads stdin. A fake tool waiting for EOF on a pipe Ruby keeps open is a harness defect; adding application EOF, timeouts or worker changes would alter the contract. Missing site source paths are setup failures, not extension behavior evidence.

The namespace-only [real-local preflight](../../tests/compat/real-local/preflight.sh) is a separate prerequisite. Passing it proves neither OCI startup nor the real Nix/OpenSSH tier, and never promotes a fake-process case to real integration evidence.

## Evidence tiers and isolation

1. **Source/adapter:** unit-like schema, serializer, gen-data client fixtures and hook stage contexts. Fast and bounded; no claim of packaged dependency or network parity. A hook-stage harness cannot prove future native deployment order.
2. **Packaged semantic tools:** import frozen nix/package.nix with shallow pkgs override for git/openssh/nix only. Tool derivations provide all exercised binaries (nix plus nix-copy-closure/nix-env/nix-collect-garbage/nix-shell where relevant; ssh; git). Dispatch on tool, host, exact argv, stdin digest and per-causal-stream occurrence. Fail unexpected invocations. Do not use one global FIFO under concurrency. Preserve original runtime/package path effects.
3. **Real local integration:** original standard package and candidate, real local Nix minimal synthetic flakes, isolated loopback SSH target with disposable root/profile/filesystem and fixture credentials, local-only Git origin. Real external startup/eval/SSH costs are measured separately from fake-process overhead. Network egress restricted; no fleet endpoints, production credentials, API writes or live configuration mutations.
4. **Protected mutation environment:** disposable VM/container with isolated home/cache/store/profile/GC-root paths and nonproduction SSH/API endpoints for build/generation/deploy/reboot/GC. Host PATH stubs alone cannot protect hardcoded /nix roots, localhost absolute executables or scripts. Never run a destructive catalogue command in the host checkout to “see what happens.” Later authorization and environment setup remain lead-owned.

Environment per run includes fresh synthetic CWD/config, private HOME/XDG caches, no inherited SSH_AUTH_SOCK, a pinned restrictive SSH config/known-hosts, controlled Nix config/store where applicable, dummy Git identity and no remotes outside fixture, explicit PAGER/TTY/color settings. Record only allowlisted nonsecret environment. Safety enforcement is harness-level isolation, not a speculative new confctl capability sandbox.

## Observation and comparison format

Minimum provenance: run/case ID; UTC date; OS/kernel/architecture; CPU/memory and scheduler contention notes; package/store paths and dependency versions; reference/candidate source and fixture digests; argv as array, CWD/PWD, environment allowlist, tty/term width, cache mode; timed versus traced mode; seeds; stdout/stderr bytes; process exit or signal; start/end events and child tree; before/after filesystem manifests. Hash/store raw artifacts and link the exact command needed to reproduce the case.

Use a neutral schema consumed by both runs; never import prototype internal types as the oracle. Per-process raw events include tool identity, PID/parent correlation, host semantic key, argv, stdin/stdout/stderr payload references, start/end, exit/signal and mutation events. For concurrency compare **causal partial order**: per-host status sequence, hook completion before evaluation, copies complete before activation, all workers before state save. Independent hosts may interleave. UI row order, prompt order, generated-array order and selected failure cleanup are still strict where source requires them; do not globally sort transcripts to conceal differences.

Allowlist ephemeral normalization only with field path and reason: owned temporary root, generated log timestamp, temp PID/random suffix, correlation PID and elapsed display values when not the subject under test. Map relationships consistently (same root/suffix remains same token), validate original form, retain raw. Stable store inputs/revisions, machine/role order, errors, exit statuses/signals, missing/created/deleted files, content/mode/link changes and mutation ordering are not “noise.” File timestamps may be ignored only when not part of tested generation age/name behavior.

Mismatch result categories: unexplained regression; external dependency variability needing fixture tightening; nondeterministic-but-causally-valid ordering; accepted P difference with named decision. A failing candidate must never trigger automatic re-record of reference. For implemented compatible surface the gate is **zero unexplained mismatches** across its required cases; unsupported command guards must also show zero external effects.

## Measurement phases

1. **Ruby attribution:** immutable original package, startup/help, ls, status none; existing-generation/default-building status measured separately only where protected and feasible. Capture separate diagnostic traces for process counts, Ruby allocation/CPU/startup and Nix/SSH phases. Trace overhead is not benchmark wall time.
2. **Bounded Go differential:** same fixtures/settings/queries/concurrency. Confirm correct help/ls/status none plus both site workflows and unsupported guards before reporting speed. Keep native full command help inventory distinguishable from unsupported execution. Full builtin characterization continues independently of Go implementation scope.
3. **Paired timing:** help, ls and status none at inventories of 1/10/100/1000; extension manual/hook cases at suitable same sizes; non-TTY automation and fixed PTY interactive cells. At least30 randomized paired warm samples per cell, repeated in two independent sessions. Record pair order seed, all raw samples, failures and resource usage. Warmup policy declared; never silently drop slow or failed samples.
4. **Cache/latency separation:** fresh application/config cache versus warm; isolated fresh Nix/store tier only if setup cost and cache definition recorded. Do not label “cold disk” without controlling OS cache. Same fixture Nix/SSH latency distributions for both candidates; separate fixed-latency/failure stress cases from real local integration. Extension policy caps/timeouts/cache experiments separate from source-compatible scheduling.
5. **Decision:** report interactive time-to-first-useful-output/prompt and total latency distributions (median/tails plus uncertainty), CPU and peak RSS, subprocess counts and phase attribution. Report absolute time saved as well as ratios. No fixed rewrite cutoff was accepted; weigh repeatable user-visible benefit, Ruby-free packaging, extension effort, maintenance and compatibility gaps.

If reference time is R (Ruby/control work) + E (unchanged external critical-path work), even eliminating R gives speedup at most (R+E)/E. With a core speedup s the bound is (R+E)/(R/s+E). Under concurrency E is critical-path time, not sum of child durations. A faster language cannot remove Nix evaluation, SSH/network delays or build time merely by replacing the CLI; redundant-evaluation elimination is a separate optimization experiment. Improvements to help/startup may still be valuable despite a small deployment-wide ratio.

Go/no-go evidence must include correctness failures, confidence/repeatability, practical interactive latency, package closure and maintenance/SDK costs. A stop/reshape result is valid if gains disappear with real Nix/SSH, compatibility cost is disproportionate, or smaller Ruby/Nix optimizations deliver the benefit. A positive PoC decision authorizes planning a next slice, not claiming full deploy parity or merging production defaults.

## Quick and longer checks

Quick: static command-count/source-link/catalogue-to-fixture coverage; fixture schema validation; deterministic fake-tool smoke cases; source-safe unsupported guards; core selector/formatter parity; prototype unit checks/format/vet as implementer chooses; SDK/site state and pipe framing/error tests. Exact package/dependency test invocations follow repository guidance and lead coordination.

After committed deliverable, quick checks and independent review: long/uncertain local Nix/SSH/protected tests and benchmark matrix through a fresh verification watcher under session policy. Keep ordinary reference runs and traced runs distinct. Lead owns review, logs/portal and final evidence-led recommendation. No merge, production deployment, fleet/helper rewrite or session lifecycle cleanup is implied by this package.
