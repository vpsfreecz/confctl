## Shared parser and option contract

[App setup, lines 13–35](https://github.com/vpsfreecz/confctl/blob/cc40679d267165aecfa569128438bb55fe910268/lib/confctl/cli/app.rb#L13) configures GLI with normal subcommand option handling, preserved argv, strict arguments and hidden undescribed commands; sets `Thread.abort_on_exception = true`; and exposes global `-c/--color` with values `always|never|auto`, default `auto`. With `IN_NIX_SHELL` present, startup sets `TMP` and `TMPDIR` to `/tmp`. There is no application-declared version flag in this setup. The exact `--help` and `--version` inputs are O below; other framework aliases, no-command behavior and uncovered parser diagnostics remain **U** (`parser.framework`). Do not infer them from another CLI library.

**O:** the accepted [parser-help reference](../../tests/compat/expected/parser-help.json) records `--help` exit0, 1269 stdout bytes and empty stderr; [parser-version](../../tests/compat/expected/parser-version.json) records `--version` exit1, empty stdout and 57 stderr bytes (`confctl: version unknown`, then `error: confctl: version unknown`, each newline-terminated). Their exact fixtures, packaged semantic-tool environment and raw hashes are in [provenance](../../tests/compat/expected/provenance.json). The VERSION constant 3.0.0 is not registered as GLI's version; a successful native version response would not preserve this input's behavior.

Positionals below quote the declared usage. Only methods explicitly calling `require_args!` enforce its count; GLI declarations alone must not be mistaken for runtime argument validation. That helper rejects missing/extra args and adds “options must come before arguments” when an extra argument starts with `-` ([lines 41–62](https://github.com/vpsfreecz/confctl/blob/cc40679d267165aecfa569128438bb55fe910268/lib/confctl/cli/command.rb#L41)). Option placement, `--`, short clusters, negation, repeated flags, dash-prefixed positionals and underscore/hyphen handling require `parser.placement` observations. Most cluster/generation handlers simply use `args[0]`/`args[1]` without this helper.

For `ls`, the S declarations pair short `o` with value-taking `output`, short `H` with `hide-header`, and constrain `managed` to `y|yes|n|no|a|all` ([app:167–177](https://github.com/vpsfreecz/confctl/blob/cc40679d267165aecfa569128438bb55fe910268/lib/confctl/cli/app.rb#L167)). **O:** [list-attached-managed](../../tests/compat/expected/list-attached-managed.json) accepts `-oname --managed no` and prints the unmanaged name; [list-cluster-negation](../../tests/compat/expected/list-cluster-negation.json) accepts `-Honame,spin --no-hide-header --managed all`, with the later negation restoring the header. [list-postarg-option](../../tests/compat/expected/list-postarg-option.json) leaves trailing `-o spin` ineffective after the machine argument. [list-invalid-managed](../../tests/compat/expected/list-invalid-managed.json) rejects `--managed bad` with exit64 before any Nix calls. These are exact-input observations, not exhaustive parser coverage.

Shared flag groups used below (a group applies only where named):

| Group | Flags and source-declared defaults |
| --- | --- |
| **F** | repeatable `-a/--attr VALUE`, `-t/--tag VALUE`; no application default list specified; parse/selection described in [interfaces](interfaces.md#inventory-selection-and-order) |
| **Y** | `-y/--yes` switch; no explicit default in declaration; absent means no bypass in handler |
| **M** | `--managed y|yes|n|no|a|all`; unset selects managed; `n/no` unmanaged; `a/all` both |
| **N** | `-j/--max-jobs VALUE`, `--cores VALUE`; string flags, no explicit default or integer type; max-jobs falls back to configuration, cores only passed when present |
| **C** | `--commit=false`, `--changelog=true`, `--editor=true`, `-d/--downgrade=false`; negation forms/equivalences are GLI capture obligations |
| **G** | `-l/--local`, `-r/--remote`; absent both means local only; both selects both |

Other switches without an explicit default below likewise have no explicit default in the declaration. GLI effective false/nil values and aliases belong in the frozen help/parser fixtures. Do not treat every command as accepting F/Y/N/M.

All action handlers use the shared log wrapper, including commands that otherwise only read. Normal `puts`/tables/prompts go to stdout; application `warn` and GLI errors use stderr. Child-process logging and TTY behavior are separately specified in [interfaces](interfaces.md#startup-environment-and-ui). “Returns” below describes handler control flow; exact process exit statuses still require observation, especially where GLI receives non-boolean method values. Do not normalize exits/signals away.

`ask_confirmation!` runs the description block and writes `\nContinue? [y/N]: `, flushing stdout. It accepts only stripped case-insensitive `y` or `n`; empty input repeats, EOF raises. A refusal raises `Aborted`. Y skips both prompt **and description block**, unless caller uses `always: true`. `ask_action` lists keys and loops until an explicit valid key; its capitalized “default” is only presentation, not an Enter default ([command.rb:73–127](https://github.com/vpsfreecz/confctl/blob/cc40679d267165aecfa569128438bb55fe910268/lib/confctl/cli/command.rb#L73)). Fixtures: `ui.confirm`, `ui.action`, `parser.*`.

## Deployment and health checks (2)

`deploy [machine-pattern [switch-action]]` accepts F Y N, `--show-trace`, `-g/--generation`, `-i/--interactive`, `--dry-activate-first`, `--one-by-one`, integer `--max-concurrent-copy=5`, non-negatable `--copy-only`, non-negatable `--enable-auto-rollback=false` and `--disable-auto-rollback=false`, `--reboot`, `--wait-online=600` (string), `--health-checks=true`, `--keep-going=false` ([app:208–263](https://github.com/vpsfreecz/confctl/blob/cc40679d267165aecfa569128438bb55fe910268/lib/confctl/cli/app.rb#L208)). Fixtures `deploy.*` must cover flag combinations, failures and causal order:

1. Managed selection; action defaults `switch`, must be `boot|switch|test|dry-activate`; `--reboot` requires boot. Only with reboot, wait-online parses `wait` (unbounded), `nowait`, or decimal digits including zero; other strings fail. Empty selection fails.
2. Confirm machines/generation/action. Invoke old `cluster_deploy` hook **before build or generation lookup**, including old-generation and copy-only paths. Payload has machines, generation, opts and **`action: opts[:action]`**, not parsed positional action. This discrepancy is S, not a post-activation event or implicit permission to fix the payload.
3. Build or find local generations. Unless copy-only, query current targets with `min(generation count,5)` workers. Skip known equal targets: carried/test/dry-activate compare current target; boot/switch additionally require current profile target. Unknown state is not skipped. All skipped returns successfully.
4. Bulk default: interactive copy serially with per-host yes/no; otherwise concurrent copy capped by max-concurrent-copy, ordering standalone first then interleaving carried groups. Wait for copies before activation. A copy failure aborts activation; copy-only stops after copies. Copy skips also skip activation.
5. Activate serially in host generation order, then optional reboot serially, then health checks. One-by-one instead performs copy/activate/reboot/check for each host before advancing. Failure can leave preceding hosts changed; there is no cluster-wide transaction.
6. Standalone activation optionally dry-activates, then interactive choices continue/retry-if-dry/skip/abort. For test/switch use auto-rollback only if enabled and helper path exists; disable flag wins. Other actions use switch-to-configuration directly. boot/switch update profile **after** successful activation. Carried entries only set carrier profile for switch; other actions return without activation. Local/carried reboot is skipped. Remote reboot detects reduced uptime, polls every 0.3s with SSH connection keepalive limits, may time out; it is not a guaranteed cancellation of the reboot.
7. Health checks run for switch/test or boot+reboot, unless disabled. Skipped activations excluded in bulk. Interactive prompt can skip checks; failed checks offer continue/retry-all/retry-failed/abort. Noninteractive keep-going prints failure and continues; otherwise raises. Reboot skips have subtly different bulk/one-by-one downstream behavior; freeze both.

## Comparisons (2)

`changelog [machine-pattern [role-pattern]]` and `diff [machine-pattern [role-pattern]]` accept F Y N, `-g/--generation`, `-d/--downgrade`; changelog additionally `-v/--verbose`, `-p/--patch` ([app:301–352](https://github.com/vpsfreecz/confctl/blob/cc40679d267165aecfa569128438bb55fe910268/lib/confctl/cli/app.rb#L301)). Compare each host sequentially against deployed inputs, with optional TTY/PAGER. Empty selection has no explicit no-machines error.

Offline prints `<host> is offline`; no roles prints `<host>: no inputs info`; unknown revisions print `<host> @ <role> in unknown state`; unchanged prints `<host>: no changes`. Role names are sorted; pattern uses Ruby matching. Diff prints `<host> @ <role> (<url>): <old-short> -> <new-short>` with URL segment conditional. Downgrade swaps direction. Changelog fetches/reuses a Git mirror and prints log; default `--oneline --max-count=50`, verbose removes both, patch adds `-p` and removes count limit. Mirror errors print an error per entry instead of failing the whole comparison. Exact blank-line/pager/caught-error transcripts require fixtures `compare.*` ([cluster:207–295,1385–1544](https://github.com/vpsfreecz/confctl/blob/cc40679d267165aecfa569128438bb55fe910268/lib/confctl/cli/cluster.rb#L207)).
