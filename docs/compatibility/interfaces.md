Evidence: **S** unless marked **U**, **P** or exact-input **O**. See [evidence rules](README.md) and the [accepted reference index](fixtures.md#implemented-case-index). ## Startup, environment and UI

The packaged executable sets GEM_HOME/GEM_PATH to its bundled dependencies, RUBYLIB to the source lib, prepends fixed Git/OpenSSH/Nix bin paths, and execs the pinned Ruby with the original argv ([nix/package.nix:1–36](https://github.com/vpsfreecz/confctl/blob/cc40679d267165aecfa569128438bb55fe910268/nix/package.nix#L1)). A caller PATH prepend cannot override these tools. The test package must call this unchanged function with only those three `pkgs` values substituted; it must not change Ruby, gem groups, library code or startup. The ordinary package remains a separate integration/measurement oracle.

`bin/confctl` requires confctl and CLI before running App. Confctl eagerly loads libraries, then top-level regular files in CWD/scripts and calls setup hooks; app setup calls each script's setup_cli ([lib/confctl.rb:36–43](https://github.com/vpsfreecz/confctl/blob/cc40679d267165aecfa569128438bb55fe910268/lib/confctl.rb#L36), [user_scripts.rb:3–28](https://github.com/vpsfreecz/confctl/blob/cc40679d267165aecfa569128438bb55fe910268/lib/confctl/user_scripts.rb#L3), [app.rb:536–538](https://github.com/vpsfreecz/confctl/blob/cc40679d267165aecfa569128438bb55fe910268/lib/confctl/cli/app.rb#L536)). This can affect help; source registration order uses directory enumeration, not an explicit sort. **P:** the Go extension registry is static and old Ruby files are never executed. Compare builtin help without legacy registrations and site command metadata separately, not by pretending startup is unchanged.

## Inventory, selection and order

Each fresh MachineList without supplied machines constructs Nix and realizes machinesJson. Selection/transform wrappers preserve ordered host mapping and original machine-list relationship (needed for carrier lookup). Nix recursively removes `_module` entries before constructing machines. Machine metadata comes from `metaConfig`; identity from name, key/machineKey/flakeKey, carrier, clusterName, alias. Preserve custom JSON data rather than a closed typed subset that discards unknown fields. Sources [machine_list.rb](https://github.com/vpsfreecz/confctl/blob/cc40679d267165aecfa569128438bb55fe910268/lib/confctl/machine_list.rb#L1), [machine.rb:47–60](https://github.com/vpsfreecz/confctl/blob/cc40679d267165aecfa569128438bb55fe910268/lib/confctl/machine.rb#L47), [nix.rb:52–57,315–321](https://github.com/vpsfreecz/confctl/blob/cc40679d267165aecfa569128438bb55fe910268/lib/confctl/nix.rb#L52).

Machine selection precedence is exact name, then matching stable key **that passes attribute/tag filters**, then Ruby pattern over name. An exact name failing filters does not fall through; key matches all filtered out do fall through. Every attr and tag filter must pass. Attr parser tries `!=` before `=`, compares `machine[key].to_s` to string; nil becomes empty, booleans use Ruby text. Invalid filter diagnostic currently interpolates the parser's returned value, not necessarily original input. Dotted paths traverse metadata; special non-dotted fields name/key/machineKey/flakeKey/checks have computed meanings. Positive tags all required; `^tag` all forbidden. Sources [command:163–204](https://github.com/vpsfreecz/confctl/blob/cc40679d267165aecfa569128438bb55fe910268/lib/confctl/cli/command.rb#L163), [attr_filters:17–49](https://github.com/vpsfreecz/confctl/blob/cc40679d267165aecfa569128438bb55fe910268/lib/confctl/cli/attr_filters.rb#L17), [tag_filters:10–27](https://github.com/vpsfreecz/confctl/blob/cc40679d267165aecfa569128438bb55fe910268/lib/confctl/cli/tag_filters.rb#L10), [machine:173–204](https://github.com/vpsfreecz/confctl/blob/cc40679d267165aecfa569128438bb55fe910268/lib/confctl/machine.rb#L173).

Patterns use `File.fnmatch(pattern, value, File::FNM_EXTGLOB)` ([pattern.rb](https://github.com/vpsfreecz/confctl/blob/cc40679d267165aecfa569128438bb55fe910268/lib/confctl/pattern.rb#L1)). Characterize `*` crossing `/`, braces, escaping, dotfiles, bracket patterns and malformed syntax. Go filepath.Match is not a drop-in substitute. Channel selectors containing comma or `{` use their own literal-list parser instead. Fixtures `selection.precedence`, `selection.pattern`, `selection.attrs`, `selection.tags`, `inputs.channel-list`.

Numeric metadata passes through Ruby `JSON.parse` and then the same `to_s` filter/table paths; there is no explicit conversion of every number to float in the source. Preserve type and precision through the replacement's decoder. **O:** [list-numeric-metadata](../../tests/compat/expected/list-numeric-metadata.json) preserves `9007199254740993`, decimal `1.0` and `[9007199254740993, 1.0]` in all four output rows after integer equality filtering. This binds the S parse/filter contract to that exact packaged Ruby input; other numeric forms remain U, and neither JSON reserialization nor a Go formatter is an oracle.

Target defaults to name only when host.target key absent; explicit null stays null. Port defaults 22 and uses Ruby to_i. Local means target exactly `localhost`; runnable excludes carried and null target. Carried profile `/nix/var/nix/profiles/confctl-<alias with / replaced by :>`; normal profile `/nix/var/nix/profiles/system`. MachineControl itself uses the provided machine's own target. **Routing through carrier is the caller's decision**, used for status/copy/profile operations but not the site standalone runtime-kernels command. Sources [machine:80–122](https://github.com/vpsfreecz/confctl/blob/cc40679d267165aecfa569128438bb55fe910268/lib/confctl/machine.rb#L80). Fixtures `selection.carried`, `process.routing`.

## SSH and process contract

MachineControl remote argv: `ssh`, optional `-F config`, `-l root`, optional `-p port`, temporary extra options, target, **one Shellwords.join(command) string**. Localhost passes command argv directly through TTY::Command. execute raises on exit error; execute! returns result. Interactive uses root's passwd shell locally or Kernel.system SSH remotely. No generic SSH timeout is set except test-connection and reboot polling; don't add one to status parity. Bash script operations invoke `bash --norc` with script bytes on stdin. Sources [machine_control.rb:19–32,88–184](https://github.com/vpsfreecz/confctl/blob/cc40679d267165aecfa569128438bb55fe910268/lib/confctl/machine_control.rb#L19), [system_command.rb:7–8](https://github.com/vpsfreecz/confctl/blob/cc40679d267165aecfa569128438bb55fe910268/lib/confctl/system_command.rb#L7). Fixtures `process.argv`, `process.ssh`, `process.stdin`, `process.signals`.

Status query order **per host**: uptime via `cat /proc/uptime`; optionally `realpath /run/current-system` (carried profile instead); normally fetch profile generations via bash; optionally inputs JSON. Exit error at uptime/toplevel/generation returns early with any previous fields retained. Invalid/missing inputs metadata becomes unknown; arbitrary exceptions outside caught classes can abort process because Thread.abort_on_exception is true. Carried status uses carrier SSH, reads profile/machine.json inputs-info first, then profile-relative etc/confctl/inputs-info.json fallback. Non-carried reads /etc/confctl/inputs-info.json. HostList bash emits current realpath then semicolon-separated link/readlink/stat epoch/kernel target lines; links are sorted by numeric generation id after parse. Invalid link warns stderr. Sources [machine_status:35–127](https://github.com/vpsfreecz/confctl/blob/cc40679d267165aecfa569128438bb55fe910268/lib/confctl/machine_status.rb#L35), [host_list:7–56](https://github.com/vpsfreecz/confctl/blob/cc40679d267165aecfa569128438bb55fe910268/lib/confctl/generation/host_list.rb#L7). Fixtures `status.query`, `status.partial`, `status.carried`.

Normal nonzero remote commands, SSH255, process spawn error, cancellation/signal, malformed response and deadline are distinct fixture outcomes. Ruby TTY::Command's exact statuses/error text/signal propagation need runtime evidence. Cancellation of local SSH is not proof the remote command terminated. The first experiment must not silently convert item errors into whole-command failures or promise remote cancellation.

Health checks include NixOS systemd properties, builder-side commands and machine commands; machine commands require runnable. Command arguments substitute `{metadata.path}`. Desired exit status plus exact/contains/excludes stdout/stderr checks use first failed output predicate. Base retries failed checks until timeout between attempts, sleeps configured cooldown; this is **not a process execution timeout**. Sources [machine:125–170](https://github.com/vpsfreecz/confctl/blob/cc40679d267165aecfa569128438bb55fe910268/lib/confctl/machine.rb#L125), [health base:17–31](https://github.com/vpsfreecz/confctl/blob/cc40679d267165aecfa569128438bb55fe910268/lib/confctl/health_checks/base.rb#L17), [run_command:75–177](https://github.com/vpsfreecz/confctl/blob/cc40679d267165aecfa569128438bb55fe910268/lib/confctl/health_checks/run_command.rb#L75), [systemd properties](https://github.com/vpsfreecz/confctl/blob/cc40679d267165aecfa569128438bb55fe910268/lib/confctl/health_checks/systemd/properties.rb#L1). ### Deployment helper boundaries

Copy invokes nix-copy-closure `--to root@target` with toplevel and enabled rollback helper; localhost copy succeeds without subprocess; carried routes to carrier. Activation invokes `<toplevel>/bin/switch-to-configuration ACTION`, then successful boot/switch sets `nix-env -p profile --set toplevel`; carried switch sets `carrier-env` on carrier. Auto-rollback invokes stored helper with `-t TIMEOUT TOPLEVEL ACTION /run/confctl-confirm-<hex6>` in a thread, polls file for switched/switching, attempts writing confirmed up to10 times, joins activation. This connectivity confirmation precedes separate health checks; it is not a health-check transaction. Sources [nix:190–284](https://github.com/vpsfreecz/confctl/blob/cc40679d267165aecfa569128438bb55fe910268/lib/confctl/nix.rb#L190), [copy:17–46](https://github.com/vpsfreecz/confctl/blob/cc40679d267165aecfa569128438bb55fe910268/lib/confctl/nix_copy.rb#L17). Fleet netboot/kexec/rollback helper rewrites are separate scope; no synchronized fleet change is required for the experiment.

GC runs MachineControl `nix-collect-garbage`, parses stdout/stderr lines. **S discrepancy / U runtime:** CLI reads `progress.line` but Progress declares no public line reader; path? also tests nil after initial false. Characterize error/progress branches before asserting successful GC transcripts or fixing them. Sources [nix_collect_garbage:4–28,38–57](https://github.com/vpsfreecz/confctl/blob/cc40679d267165aecfa569128438bb55fe910268/lib/confctl/nix_collect_garbage.rb#L4), [CLI generation:290–303,327–337](https://github.com/vpsfreecz/confctl/blob/cc40679d267165aecfa569128438bb55fe910268/lib/confctl/cli/generation.rb#L290). ## Inputs, lockfile and Git

FlakeLock expects nodes.root.inputs, returns sorted root names; string node references or first string element of array references are used. Missing fields get placeholder values; short rev first8; GitHub derives HTTPS repo URL, git+ prefix stripped from general URL. This is the Ruby reader behavior, not a promise to fully interpret arbitrary Nix follows graphs. Source [flake_lock:22–75](https://github.com/vpsfreecz/confctl/blob/cc40679d267165aecfa569128438bb55fe910268/lib/confctl/flake_lock.rb#L22). Fixture `inputs.lock-reader`.

Update runs `nix flake update <names...>` in configuration root, optionally retries with experimental flags, rereads lock, diffs selected inputs; no-change skips commit. Set first resolves and validates all input types/override URLs; then each input runs `nix flake lock --update-input INPUT --override-input INPUT URL --output-lock-file TEMP`. TEMP includes PID+hex12. Restores all selected inputs' original metadata, pretty-serializes with newline and renames to flake.lock after **each** input. Ensure removes leftover temp; later failure can leave earlier input updated. No automatic rollback of lock on Git failure. Sources [updater:11–70](https://github.com/vpsfreecz/confctl/blob/cc40679d267165aecfa569128438bb55fe910268/lib/confctl/inputs/updater.rb#L11), [setter:14–172](https://github.com/vpsfreecz/confctl/blob/cc40679d267165aecfa569128438bb55fe910268/lib/confctl/inputs/setter.rb#L14). Fixtures `inputs.update`, `inputs.set`, `mutation.partial`.

Successful Nix process status is insufficient: cached GitHub API fallback warnings trigger explicit failure, with separate rate-limit message. This check does not roll back mutations Nix already performed. Other warnings must not be rejected indiscriminately ([nix_output_guard:4–31](https://github.com/vpsfreecz/confctl/blob/cc40679d267165aecfa569128438bb55fe910268/lib/confctl/inputs/nix_output_guard.rb#L4)). Fixture `inputs.cached-fallback`.

Optional commit calls argv `git commit [-e] -m MESSAGE flake.lock`; no explicit git add. Title `inputs: update|set <sorted names>` plus common short revision when available/same source; body revision summaries and optionally grouped mirror changelog, downgraded direction only for log. ### New extension boundary is P

Two site-owned Go executables (or one executable with two registrations) are built/pinned by Nix. Static registry supplies command/help/options/hooks without evaluating machines or running extensions. New versioned invocation-scoped protocol separates context/service traffic from interactive stdin/stdout/stderr; public SDK exposes ordered inventory/selection, settings, argv execution, prompts/tables and safe Nix literals. No daemon, native Go plugin, Ruby object emulation or recursive confctl spawning is required. Refer to the session extension-system proposal for protocol details; the accepted measurement brief takes precedence over its unaccepted timeout/worker defaults.

V1 events are rediscover.after-write and deploy.prepare. Rediscover attaches to operation (including add/rename), refreshes inventory after core write and after each mutating hook. Deploy.prepare remains before build **or** generation resolution, including copy-only. Supplying parsed action instead of old opts[:action] is an explicit new-payload correction; the known site hook ignores it. The harness must keep old observed payload and new expected payload as distinct evidence, not normalize the discrepancy out. Default caps/timeouts/locks/cache behavior remain unaccepted as builtin parity; profile any proposed new policy separately. Fixture `extension-policy.*`.
