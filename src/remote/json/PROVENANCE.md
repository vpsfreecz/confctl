# Purpose-specific Ruby JSON compatibility source

`float.rs` and `float/powers.rs` are a safe Rust translation of the Grisu2
formatter vendored by the Ruby JSON gem **2.21.2**. The source identifies
<https://github.com/night-shift/fpconv> and adds Ruby's `.0` and decimal/scientific
emission rules. Both derivative files retain the complete Boost Software License
1.0 notice. No new crate or application-wide JSON encoding policy is introduced.

Qualified originals, SHA256:

- `ext/json/ext/vendor/fpconv.c`:
  `0487fd5cf86f501876c865f6a7505e6e7d82df95ee1446533838f89798ed74a2`
- `ext/json/ext/generator/generator.c` (`generate_json_float`):
  `76bb6f5530d4e0f378b0c4b6eba8f525127bcb254435431cb93f184d77f57f4d`

`json.rs` is private to the built-in runtime-kernel state writer and the netboot
builder generation/index pretty writer. Parsed Integer
tokens preserve arbitrary precision and insertion order. Parsed Float tokens
convert to binary64 before the frozen formatter; retaining their original decimal
lexemes or using a different shortest-roundtrip formatter would change bytes.
Nonfinite results fail encoding before state replacement. Ruby's nesting limit
of 100 applies to parsing and generation; this adds no object/string schema.

`ruby-floats.json` contains 2,434 original Ruby 3.4.9 / JSON 2.21.2 outputs from
exact binary64 bit patterns: both signed zeros, subnormals, finite extremes,
precision/notation thresholds and neighbours, exponent/mantissa examples, and a
fixed-seed 64-bit sequence. Assertions compare generated bytes as well as parsed
persistent values. `ruby-conversions.json` preserves original port conversion,
integer/float/empty-container and nesting observations. `ruby-semantics.json`
contains the preceding purpose-specific permissive-root/String observations.
These are expected bytes from Ruby, not values generated by the Rust port.

The test-only generator is `tests/compat/site/probe_runtime_numerics.rb`; run it
with the locked original Ruby/JSON environment. It writes JSON to stdout and
never probes hosts or mutates runtime state. Expected fixtures are frozen inputs;
do not regenerate them to accommodate a candidate mismatch. The first semantics
probe and full raw startup/stdout/stderr receipts are retained in the development
session evidence. Candidate byte parity requires passing the Rust tests; the
original probe alone establishes only the expected results.
